## 1. 当前结论

已完成并有文件证据的部分：

- Jetson + D435i + RealSense 对齐深度 + YOLOv8 视觉链路已建立，Windows 可通过 `http://192.168.8.100:8090/` 查看实时画面。
- 使用 v3 眼在手上标定的 `wrist_d435i_to_tcp_corrected.yaml` 进行相机坐标到机械臂基坐标的换算。
- 水瓶识别已改为 YOLOv8 COCO `bottle`（类别 `39`），不再以“红色物体”作为是否存在水瓶的判定。
- 针对透明瓶身，程序在下部红色标签处取得可靠深度，但将 YOLO 水瓶框中心作为三维目标像素，已实现标签采样点到水瓶中心的偏差补偿。
- 抓取侧已保存抓取拍照点、瓶上方参考点、抓取点；旧版抓取后回到拍照点/松开夹爪的结果文件仍在。
- `bottle_pick_place_demo_v3.py` 已实现抓取—放置的 S1~S8 代码流程，且通过 Python 语法编译。

尚不能称为“已完成”的部分：

- 三个放置侧位姿文件仍为占位值，`confirmed=false`；完整抓取—检测放置位—放置—回拍照点流程尚未具备可安全执行的真实放置点。
- Windows 中的新 Demo 源码是否已经同步到 Jetson，以及当前 Jetson 是否使用同一版本，未在本次 Windows 盘点中重新确认。
- 新的“YOLO 中心补偿”版本完成了无运动识别验证，但尚未在该版本上重新做实机抓取运动验证。

## 5. 新版抓取—放置 Demo 的实际流程

程序：`bottle_pick_place_demo_v3.py`

| 阶段 | 程序行为 | 依赖 |
|---|---|---|
| S1 | 到抓取拍照点 | `grasp_photo_pose_v3.json` |
| S2 | YOLOv8 检测水瓶，连续稳定取样 | 相机、YOLO、`bottle_target_once_v3.py` |
| S3/S4 | 经过瓶上方参考点，到抓取点，停稳后夹爪闭合 | `bottle_above_pose_v3.json`、`grasp_pose_v3.json` |
| S5 | 经瓶上方参考点，前往放置拍照点 | `place_photo_pose_v3.json` |
| S6 | 在放置 ROI 内统计 YOLOv8 水瓶数量 | 放置拍照位和 ROI |
| S7 | 0 个原位；1 个 X−12.5 cm；2 个 Y+12.5 cm；3 个及以上 X−12.5 cm 且 Y+12.5 cm；放置上方点与释放点同步偏移 | `place_mid_pose_v3.json`、`place_pose_v3.json` |
| S8 | 返回抓取拍照点 | `grasp_photo_pose_v3.json` |

当前程序参数：

```text
默认机械臂地址：192.168.11.11
ArmGateway：127.0.0.1:6200
夹爪力：60 N
夹爪速度：40
抓取 Z 额外偏移：-0.01 m
到位容差：3 mm
```

重要限制：放置侧三个 JSON 当前均为：

```text
placeholder: true
confirmed: false
```

因此不带参数直接执行新 Demo 时，它会提示未教学的放置位并返回 `2`，不会进入物理运动。不要使用 `--allow-placeholders` 绕过该检查。

## 7. 当前风险与注意事项

1. 抓取拍照点是手眼坐标换算的固定前提。相机或机械臂实际拍照姿态变化后，不能继续使用旧拍照位姿和旧标定。
2. 代码和历史资料中出现过 `192.168.11.11` 与 `192.168.30.11` 两个控制器地址；执行前应以当前 ArmGateway 的实际连接配置为准，不要自行混用。
3. 不能同时让 Xbox 手柄速度控制和自动 MoveBlend 流程争抢控制权。
4. 新 Demo 的文档字符串明确说明它没有额外的关节突跳、姿态漂移或速度安全保护；它是演示流程，不应在未确认所有点位前直接执行。
5. 放置位数量探测异常时，新 Demo 当前仍按“0 个水瓶”处理；正式连续运行前，建议把探测失败策略改为“停止并等待人工确认”。
6. `place_photo` 与 `place` 已在 Jetson 端验证过可运动；当前用户反馈“放置位上方”不对，需重新示教 `place_above`（实际写入 `place_mid_pose_v3.json`）。

### 三轮连续执行入口

Jetson 上的入口程序为：

```bash
python3 /home/nvidia/calibration/run_three_cycles_v3.py
```

默认最多执行 3 轮。每轮在抓取拍照位等待水瓶识别 30 秒；30 秒内没有识别到水瓶时，程序正常退出，不启动下一轮。也可用 `--cycles` 和 `--no-bottle-timeout` 调整轮数与等待时间。
