# V4 数据传输与部署设计

## 1. 推荐硬件拓扑

Jetson 是任务大脑，但不承担底盘电机、机械臂伺服等实时闭环。Jetson、机械臂控制器、车载前视相机和底盘全部连接同一台 5 GHz 路由器。当前已确认控制器为 `192.168.30.11`、前视相机为 `192.168.30.120`、底盘为 `192.168.30.200`；Jetson 的 Wi-Fi IP 和路由器管理地址仍待现场确认。

```text
                       5 GHz 路由器（192.168.30.0/24）
                    ┌───────────┼─────────────┐
                    │           │             │
       Wi-Fi        │       LAN/Wi-Fi     LAN/Wi-Fi
 Jetson（Wi-Fi IP待确认）│           │             │
 ┌──────────────────┴─┐  前视相机          底盘 192.168.30.200
 │ 任务状态机          │ 192.168.30.120     ┌──────────────┐
 │ 地图/Nav 客户端     │──拉取视频──────────▶│ 本地导航/避障 │
 │ 双相机视觉推理      │                    │ 电机实时闭环   │
 │ ArmGateway :6200   │──导航目标/停止─────▶└──────────────┘
 └──────────┬─────────┘
            │ LAN: 指令/状态 + 腕部视频
            ▼
   控制器 192.168.30.11（直接连接路由器）
 ┌───────────────────────────────┐
 │ 机械臂 SDK / 轨迹执行          │
 │ 腕部相机 USB/CSI ── RTSP 输出  │
 │ 夹爪 RS485/IO ── 控制器服务    │
 └───────────────────────────────┘
```

关键原则：视频由 Jetson 主动拉取；命令由 Jetson 主动发起；底盘和控制器只在本机完成实时控制。Wi-Fi 抖动不会直接进入伺服环。

## 2. 完整数据路径

| 阶段 | 源 → 目的 | 数据 | 推荐传输 | 频率/时限 |
|---|---|---|---|---|
| 地图标点 | UI/任务文件 → Jetson | `map` 坐标 x/y/yaw | 本地 JSON 或 REST | 单次 |
| 粗导航 | Jetson → 底盘 | 导航 goal、mission_id、seq | TCP JSON 或 ROS2 Nav2 action | 单次；状态 5–10 Hz |
| 前视粗定位 | 前视相机 → 路由 → Jetson | RGB + 深度 | Orbbec SDK v2 网络流 | 15 fps |
| 视觉对准 | Jetson → 底盘 | bearing、forward、stop | TCP JSON | 每次小步闭环 |
| 腕部精定位 | 腕部相机 → 控制器 → Jetson | RGB + 对齐深度/点云 | RTSP + 深度厂商流，或 ROS2 | RGB 20–30 fps |
| 机械臂轨迹 | Jetson ArmGateway → 控制器 | MoveBlend/轨迹 | 现有 JSON TCP + SDK | 每段一次 |
| 夹爪 | Jetson → 控制器 → RS485/IO | open/close/force/speed | 控制器 JSON TCP 服务 | 单次 + 状态确认 |
| 监控日志 | 各适配器 → Jetson | seq、时间戳、状态、故障 | 本地 JSONL | 每事件 |

不建议把两路原始视频先送到底盘再转发，也不建议让 Jetson 通过 Wi-Fi 直接发送轮速或关节伺服周期命令。

## 3. 坐标链

上线前必须得到三条新外参，v3 外参因安装结构变化而无效：

```text
map ──定位──▶ base_link ──固定标定──▶ arm_base
  └─────────▶ camera_front（固定在车体）
arm_base ──机械臂正解──▶ tool0 ──新手眼标定──▶ camera_wrist
```

前视相机只负责 `bearing_rad + distance_m`，误差允许较大；底盘到位后腕部相机必须输出 `position_base_m=[x,y,z]` 且 `frame_id=arm_base`。任务层拒绝过期、低置信度、NaN 或超出机械臂安全包络的目标。

推荐时间同步：路由器或 Jetson 提供 NTP/chrony，底盘与控制器同步到 Jetson；检测结果携带采集时间，而不是推理完成时间。默认最大结果年龄 0.5 秒。

## 4. 建议地址与端口

| 节点 | 地址 | 端口 | 用途 |
|---|---|---|---|
| 路由器 | `192.168.30.1`（待确认） | — | DHCP 静态租约/NTP 转发 |
| Jetson | 待确认 | `6200` | 本机 ArmGateway（绑定 `127.0.0.1`） |
| Jetson | 待确认 | `8088` | 双相机检测服务；任务程序通过 `127.0.0.1:8088` 访问 |
| 控制器 | `192.168.30.11` | `5868`/厂商值 | 直接连接路由器；机械臂 SDK |
| 控制器 | `192.168.30.11` | `6201` | 建议的夹爪桥接服务 |
| 控制器 | `192.168.30.11` | `8554`（待确认） | 腕部相机经控制器输出的视频流 |
| 底盘 | `192.168.30.200` | `7001` | 直接连接路由器；导航 JSON TCP 服务 |
| 前视相机 | `192.168.30.120` | `8090` | Gemini 335Le；Orbbec SDK v2 网络设备流 |

实际设备不支持这些端口时只改配置/适配器，不改任务状态机。视频和控制最好分 VLAN 或至少启用 WPA2/WPA3、关闭公网端口映射。

## 5. 底盘 JSON-lines 协议

一行一个 UTF-8 JSON，请求和响应使用相同 `seq`。长任务响应应在到达或失败后返回；若厂商 API 是异步的，底盘桥接程序负责轮询并最终响应。

```json
{"seq":1,"cmd":"health"}
{"seq":1,"ok":true,"localized":true,"battery_pct":87}

{"seq":2,"cmd":"navigate","frame":"map","goal":{"x":2.0,"y":0.8,"yaw":0.0}}
{"seq":2,"ok":true,"state":"SUCCEEDED","pose":{"x":2.01,"y":0.79,"yaw":0.01}}

{"seq":3,"cmd":"align","bearing_rad":0.12,"forward_m":0.14}
{"seq":3,"ok":true,"state":"SUCCEEDED"}

{"seq":4,"cmd":"stop"}
{"seq":4,"ok":true}
```

底盘自身必须实现激光/深度避障、急停、目标超时和断联停车；Jetson 的 stop 是上层补充，不替代硬件安全。

## 6. 视觉服务返回协议

Jetson 视觉服务向任务程序暴露统一 HTTP 接口，从而把 RTSP、ROS2、厂商 SDK 和 YOLO 版本隔离在视觉进程内。

```text
GET /health?camera_id=front
GET /detect?camera_id=front&label=bottle
GET /detect?camera_id=wrist&label=bottle
```

前视响应：

```json
{
  "detected": true,
  "confidence": 0.91,
  "bearing_rad": 0.12,
  "distance_m": 0.86,
  "frame_id": "camera_front",
  "timestamp_s": 1788916000.25
}
```

腕部响应必须经过深度反投影、`tool0→camera_wrist` 手眼变换和机械臂正解：

```json
{
  "detected": true,
  "confidence": 0.97,
  "distance_m": 0.24,
  "position_base_m": [0.432, 0.029, 0.180],
  "frame_id": "arm_base",
  "timestamp_s": 1788916000.31
}
```

## 7. 控制器侧夹爪协议

夹爪物理连接已移动到控制器，v4 不再调用旧的 `/dev/ttyUSB0` 脚本。控制器桥接服务负责把以下消息转换成厂商 SDK、Modbus RTU 或数字 IO：

```json
{"seq":1,"cmd":"gripper_state"}
{"seq":1,"ok":true,"enabled":true,"position":0,"fault":0}

{"seq":2,"cmd":"gripper","action":"close","force_pct":60,"speed_pct":40}
{"seq":2,"ok":true,"reached":true,"object_detected":true}
```

真实抓取建议要求 `object_detected=true` 或电流/位置闭环确认。本 demo 的通用接口先检查 `ok`；拿到控制器协议后应在 `ControllerGripper` 中增加该字段的硬性判断。

## 8. 状态机与失败策略

现场联调统一使用以下步骤编号：`S1` 地图标点、`S2` 系统预检、`S3` 小车粗导航、`S4` 前视粗识别、`S5` 小车视觉对准、`S6` 机械臂观察位、`S7` 腕部精定位、`S8` 抓取规划与安全检查、`S9` 接近并抓取、`S10` 垂直抬升、`S11` 托盘放置、`S12` 回 Home 并完成任务。

```text
PREFLIGHT → NAVIGATING → FRONT_SEARCH → BASE_ALIGN
    → WRIST_LOCALIZE → PICK → PLACE → COMPLETE
          任意异常 ────────────────→ SAFE_ABORT
```

SAFE_ABORT 会立即发底盘 stop、停止/释放机械臂控制权，并保持夹爪最后状态。抓到物体后异常时自动松爪可能砸落物体，因此必须由操作者确认后恢复。

## 9. 真实设备上线顺序

1. 锁定五个静态 IP，验证 Jetson 到各设备的丢包和延迟。
2. 单独验证底盘 `health/pose/navigate/align/stop`，确认断联停车。
3. 修改现有 ArmGateway 的控制器 IP，但在 v4 目录复制配置后再改，不覆盖 v3 配置。
4. 在控制器侧实现夹爪桥接，单独验证开、闭、物体检测和故障码。
5. 用 `scripts/start_v4_front_vision.sh` 打通 Gemini 335Le，再接入腕部视频；测量同时传输时的带宽和 99% 延迟。
6. 重新做前视外参、腕部手眼标定、`base_link→arm_base` 标定。
7. 示教 v4 的 home/observe/place_above/place，先空载低速运行。
8. 在配置中收紧工作空间，逐项把三个 calibration `confirmed` 改为 true。
9. 最后确认 `hardware_confirmed=true`，以 `--mode real` 运行；首次运行有人按住急停。
